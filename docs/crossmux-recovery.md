# 双系统恢复与风险应对

适用于实验预发布 `v0.1.5-coexist-zh` 与专用 CrossMux `1.6.5-x4pro-coexist`。完整安装见 [共存指南](crossmux-coexistence.md)。最终两槽是 CrossMux 与 Muse，没有常驻 CrossPoint；旧 `v0.1.4-zh` 的 CrossPoint 恢复步骤见 [旧版指南](install.md)。

**第三方应用更新可能导致无法启动或数据丢失。** 用户已确认本配套版本启动与双向切换，但以下故障恢复操作尚未单独实机验收，不能保证任何故障都可恢复，也不能假定当前 bootloader 支持自动回滚。

## 正常启动但切换失败

停止反复升级，记录当前版本、菜单提示和操作过程。核对两个镜像是否来自同一配套发布；不要用普通 Nightly、改名镜像或不同板型镜像补槽。

Muse 显示 **恢复未验证** 意味着另一槽未通过允许的完整镜像校验，不是建议跳过校验。CrossMux 拒绝切换或拒绝 SD 文件时，也不要禁用签名检查。重新核对本地文件、SD 回读、发布清单和版本对应关系，必要时请维护者诊断。普通配对或显示问题先检查 Wi-Fi、Muse 命令和连接状态，不先清空 NVS、重置配对或刷其他镜像。

## Muse 界面或网络初始化失败，CrossMux 槽仍完整

在 **Muse 开始启动时按住右键至少 1.2 秒**。此路径在 Muse 网络、存储和屏幕初始化前检查配套 CrossMux 的准确长度与 SHA256，通过后选择 CrossMux 并重启。

这条路径仍依赖正确的 CrossMux 槽和设备能执行 Muse 启动代码；右键不能修复损坏的 CrossMux，也不能绕过摘要校验。若没有切换，不盲目改硬件引脚、不反复刷写。

## CrossMux 主界面失败，但能进入 SD 恢复界面

X4 Pro 的逻辑 **DOWN 对应右侧按键**。从电源键开机或唤醒时按住 **DOWN + POWER**，CrossMux 在电源唤醒路径检查 DOWN，可进入 SD 固件恢复界面。其他重启方式未必触发该条件。

**专用共存配置在此恢复界面也只接受与当前 CrossMux 配套、已签署的 Muse 镜像。它不能加载普通 CrossMux `.bin`，也不能用发布页的 CrossMux 文件修复 CrossMux 自身。** 这项限制保护另一槽；不要以“恢复模式”为由绕过它。

如果 SD、显示或 CrossMux 启动代码本身失败，可能无法到达此界面。尚未取得本版本 DOWN 开机恢复的独立实机验证；能正常双向切换不等于此路径已经测试。

## 两槽无法启动，或需修复 CrossMux 自身

先停止写入。USB 恢复是否可行取决于实际设备、数据适配器、串口下载权限及厂商锁定状态；USB 锁定设备可能需要官方工具或厂商协助。

按以下顺序让具备设备恢复经验的人诊断：

1. 只读识别芯片型号、Flash 容量及下载模式是否可访问，确认是该台 X4 Pro / ESP32-S3。
2. 若设备允许，先完整读取 Flash 备份并在本机保存校验值。备份可能包含 SDK token、配对资料和 Wi-Fi 信息，按私人文件保管，不上传到问题报告。
3. 从设备读取并解析**实际分区表**，核对各应用槽、启动选择数据与 NVS。不要把仓库分区表或别台设备偏移当成该设备的真实布局。
4. 只有确认镜像板型、准确大小、摘要、目标应用槽和启动选择方式后，才制定匹配该设备的 **app-only** 恢复操作。保留 NVS、bootloader、分区表与 eFuses；需要修改启动选择数据时也须先核实其布局与状态。

这里不提供未经设备核实的 Flash 写入偏移。**不要运行 `idf.py flash`、整机 factory/full-flash 包、全 Flash 擦除或修改 eFuses；不要假定重启会自动回滚。** 芯片识别、Flash 备份和实际分区确认完成以前，不执行写入。

## 降低风险与反馈

安装前备份 SD；保存配套公开文件、`SHA256SUMS` 与 `verification.json`，本地单独保管个人 Muse 镜像。使用健康 SD 卡、保持电量充足，每次传输完整回读；更新时不拔卡或断电。普通 CrossMux OTA 已禁用，后续只采用明确支持双系统的配套升级方案。

报告可包含公开版本、操作步骤、错误提示与屏幕照片。不要附 SDK token、签名私钥、个人 `.bin`、完整 Flash/NVS 备份、Wi-Fi 密码或未经脱敏的固件日志。字体路径的主机测试不能证明换字体后的实机槽安全；出现异常先停止升级并收集可公开的证据。
