# 左键呼叫 Muse（开发中）

目标版本为 **`0.1.6-call-zh` 实验版本**，目前是源码开发功能，暂无该版本公开 release，尚未完成实机验收。已发布的 `0.1.5-coexist-zh` 资产、版本与摘要保持不变。

这个功能让 X4 Pro 的左键发送固定触发消息给已配对的 Muse，由 Muse 读取用户保存的 **「X4 Pro 左键预设」**，执行其中明确的任务，再把结果回传阅读器。固件不保存任务正文、不猜测最近聊天中的任务，也不会替用户建立云端计划。

## 先在 Muse 中保存预设

官方说明 Muse 的记忆跨对话持续，并且 Memory 文件可直接读取、编辑：[How We Designed Muse](https://introducing.muse.ai/)。官方也说明 Muse 的独立云端 VM 可存储文件、创建自定义 skills：[How We Built Safety Into Muse](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse)。

这些是持久保存指令的基础，**不是一个公开的「左键预设」API**。本项目未确认官方提供统一的预设 API、手机菜单入口或 skill 文件路径，因此通过 Muse 聊天请它实际保存、读回与修改。仓库里的维护 skill 不会自动安装到用户的 Muse。固件依赖 Muse 主动读取持久指令并调用设备工具，按键本身不能保证预设已保存或任务已完成。

将下面模板复制给自己的 Muse，把方括号内任务改成需要的内容。此消息只用于设置，不立即执行任务：

```text
请保存名为「X4 Pro 左键预设」的持久指令 / Memory，不立即执行。

任务：[在这里填写我希望按左键时执行的明确任务，可随时修改。]

触发规则：只有收到已配对 X4 Pro 发来的左键触发消息才执行。运行上下文会包含 call_id 和 device_id；使用本次上下文的准确值，不沿用上次 ID，不操作其他设备。

权限边界：只在我已有授权的范围内执行此预设，不把按键当成新增授权。需要发送消息、改文件、修改日历、购买或其他副作用时，遵守 Muse 原有授权与确认要求；缺少权限时明确告诉我。

如果预设未保存、无法读取、已遗忘或任务不明确，请返回设置提示，不猜测最近聊天中的任务，不默认执行最近的模糊请求。

每次完成、失败、缺少预设或需要进一步授权时，用本次 call_id 调用这台设备的 pocket.complete_call，参数是 call_id 和 text。text 使用适合黑白屏的简洁中文纯文本，不用 emoji、Markdown 表格或依赖颜色；长度为 1 到 3072 个 UTF-8 字节，超出时先摘要。不要只发普通 pocket.set_status 作为完成结果。

保存后请重新读取实际保存的记录，向我复述任务、权限边界和完成回调规则，并给出我能打开或编辑该 Memory 的实际位置。不要只说「记住了」而不检查记录。
```

默认可采用以下只读任务，替换模板里的任务占位：

> 汇总今天的重要事项，只读取我已授权的数据，最多列五项并说明缺少的信息。不发送消息、不修改日历或文件、不购买东西。没有可用数据时明确说明，不根据最近对话猜测待办。

保存后再发送一条新消息验证跨消息检索：

```text
请重新读取「X4 Pro 左键预设」，只做 dry-run：复述将执行的任务、授权边界和回调方式，不实际执行、不调用设备完成命令。如果找不到记录请明确说明。
```

以后直接在 Muse 聊天中要求 **修改同名预设，不立即执行**，提供新任务，再要求重新读取并复述。实际保存和读回成功后，才在阅读器上触发。本项目没有替你完成云端配置。

## 按键与屏幕

1. 在 Muse 系统中，长按左键 **2 秒**呼叫已配对 Muse；已配对时在设置菜单中触发，会先关闭菜单。未配对时不呼叫。只有初始化设置尚未完成、且非等待配对确认时，才保留左键长按 **5 秒**重置设置；日常已配对使用不会清除配对。配对确认中长按不确认、不呼叫，确认仍用短按。
2. 阅读器显示 **正在呼叫 Muse**。已有呼叫等待结果时，重复长按不会重发，短按也不会提前退出等待；普通 `pocket.set_status` 不能覆盖呼叫、结果或错误提示界面。
3. 只有 Muse 调用 `pocket.complete_call`，且 `call_id` 与当前等待请求精确匹配，才显示返回结果。HTTP 2xx 只表示请求被接受，不表示任务完成。
4. 结果以中文纯文本在原角色图像区域分页显示，底部显示当前页与总页数。**左键短按**翻下一页；末页再短按返回角色图。原角色图保留，无须重新下载。没有结果正文的错误提示也可用短按左键清除。
5. 右键仍打开设置；电源键的刷新、休眠和恢复操作沿用原规则。呼叫不修改 CrossMux 镜像、恢复摘要或配对存储。

完成命令的参数形状如下，ID 必须使用实际收到的值，不能复制这个占位 ID 执行：

```json
{"call_id":"本次触发消息中的准确ID","text":"今天的重要事项：……"}
```

`text` 接受 **1–3072 UTF-8 字节**的有效文本，不是 3072 个中文字。普通 `pocket.set_status` 仍是最多 240 字节的短状态；它不能替代完成回调。旧 ID、不匹配 ID 和重复完成都不能冒充当前呼叫结果；超时或断线结束本地等待后，迟到回调也不会作为当前结果显示。

## 超时、断线与副作用

三分钟内没有收到匹配的真实结果时，阅读器显示 **状态未知**，不会自动重发。它表示没有确认结果，不能解释成「任务未执行」或「已取消」。断线、休眠、返回角色图或切换系统也不等于撤销已经发送给 Muse 的任务；该任务可能仍在继续执行。

先在 Muse 聊天中检查该次任务和结果，再决定是否重新触发。涉及发送消息、购买、修改数据等副作用时尤其不要盲目重复。按键只触发既有预设，副作用仍受 Muse 原有授权与确认控制；需要取消时在 Muse 中处理，阅读器没有云端取消 API。

如果没有结果，先检查配对和网络、预设是否实际保存、Muse 是否读到本次上下文及是否调用正确设备的 `pocket.complete_call`。不要先重置配对、重刷 CrossMux 或绕过签名 / 恢复校验。报告问题可提供版本、操作、屏幕提示和脱敏的 ID；不提供 token、个人镜像或私钥。

## 升级边界与验证

已安装配套双系统的设备继续使用既有 **受保护 CrossMux `1.6.5-x4pro-coexist`**，无需改动或重新刷写 CrossMux。新 Muse 将使用相同 peer 的配套签名；待新模板发布或明确提供经核验的签署模板后，在本机使用 `package_private.py` 隐藏输入自己的 SDK token，再由现有 CrossMux 的 SD 应用更新安装。不要用未签署的普通构建替代，不运行 `idf.py flash`，不写 bootloader、分区表、NVS 或 eFuses。

`0.1.5-coexist-zh` 的启动和双向切换确认不等于左键呼叫已通过实机测试。预设持久保存、真实任务触发、匹配完成回调、分页、超时与断线行为需要在新版本上分别验证。现在不能宣称已替用户保存预设、已发布 `0.1.6-call-zh` 或已完成实机验收。
